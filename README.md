# Refinement Code Review

## Article

[Refinement Code Review by Martin Fowler](https://martinfowler.com/bliki/RefinementCodeReview.html)

## Why I Find This Article Interesting

I found this article interesting because it changed the way I think about code review. Before reading it, I mainly thought code review happened when someone submitted a pull request and another developer checked the changes before merging them. The article explains that code review can also happen continuously when developers return to existing code, notice problems, and improve it over time.

I also liked the idea that software is never completely finished. As a project grows, code that seemed reasonable before may no longer be the best solution. This means developers should keep refining the codebase instead of only focusing on new features. I think this is especially important in team projects because everyone shares responsibility for keeping the code understandable and maintainable.
